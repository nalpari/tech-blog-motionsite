## 💭 서론

코딩을 오래 해온 사람이라면 알겠지만, 늦은 밤의 디버깅 세션은 절대 화려하지 않습니다. 그냥 필요할 뿐이죠.

저의 최근 야심찬 프로젝트는 의료 문서(진단서, 검사 결과지, 퇴원 요약서 등)를 사람들이 실제로 이해할 수 있는 언어로 번역하는 앱입니다. 혈액 검사 PDF를 업로드하면 그 숫자들이 무엇을 의미하는지 명확한 설명을 받을 수 있죠.

### 😰 간단한 컨셉, 복잡한 실행

**하지만 3개월이 지나자, 저는 익사하고 있었습니다.**

제 UI는 카페인에 취한 너구리 위원회가 디자인한 것처럼 보였습니다. PDF 업로드는 2MB 이상 파일에서 깨지고 있었죠. 의료 용어들은 "hypertension"이 두 줄에 걸쳐 "hyper-ten-sion"처럼 보이는 방식으로 줄바꿈되고 있었습니다. 모바일 버전은? 가로 스크롤이 의도하지 않은 기능이 되어버렸습니다.

**그리고 제 코드는?** 작동은 했지만 간신히였습니다. 함수들은 각각 세 가지 일을 하고 있었고, 테스트는 "TODO" 주석이었으며, 새로운 문서 타입마다 폭탄 해체하는 느낌이었습니다.

특히 기억나는 한 밤, 간단한 CBC 리포트에서 정의되지 않은 콜레스테롤 수치에 대한 오류를 던지는 PDF 파서를 응시하고 있었습니다.

> "이게 바로 팀 전체가 나 혼자일 때 일어나는 일이지" 라고 생각했죠.
>

## 🌟 모든 것이 바뀐 그날 밤

그때 저는 **Claude Code의 에이전트 시스템**을 발견했습니다. 모든 것을 하려는 단 하나의 AI가 아니라, 각자의 전문성과 컨텍스트를 가진 전문화된 AI 팀원들이었죠.

**"컨셉이 즉시 와닿았습니다:"** 압도된 하나의 AI에게 디자이너, 개발자, 테스터, 의료 번역가가 되라고 요청하는 대신, 특정 문제에 대한 특정 전문가를 소환할 수 있었습니다.

```
claude

```

그 간단한 명령이 솔로 개발자로서 경험해본 적 없는 것을 열어주었습니다 - 실제 팀원을 갖는 것.

---

## 👥 새로운 팀을 만나다

### 🎨 디자인 시스템 집행자 (Design System Enforcer)

첫 번째 호출:

```
/agents design-system-enforcer

```

**저는 UI 혼란을 설명했습니다:** *"PDF 업로드가 모바일에서 깨지고, 의료 용어가 끔찍하게 줄바꿈되고, 문서 뷰어가 태블릿에서 쓰레기처럼 보입니다."*

돌아온 것은 단순한 수정이 아니라 체계적인 사고였습니다. 진행 표시기가 있는 적절한 파일 업로드 처리, 문서 보기를 위한 반응형 브레이크포인트, 한 페이지 검사 결과든 스무 페이지 퇴원 요약서든 작동하는 깔끔한 레이아웃을 제공했죠.

결과는? 제 문서 뷰어가 찌그러지고 읽을 수 없는 텍스트에서 복잡한 의료 PDF를 실제로 탐색할 수 있게 만드는 깔끔한 인터페이스로 바뀌었습니다.

### 🏥 쉬운 언어 임상의 (Plain-Language Clinician)

다음 차례:

```
/agents plain-language-clinician

```

전형적인 검사 결과 스니펫을 제공했습니다: *"혈청 크레아티닌 수치는 정상 범위 내 사구체 여과율을 나타냅니다."*

**돌아온 답변:***"귀하의 신장 기능 검사는 정상 결과를 보여줍니다. 이는 귀하의 신장이 혈액에서 노폐물을 적절히 걸러내고 있다는 의미입니다."*

하지만 여기서 인상적이었던 것은 - 맥락을 이해한다는 것이었습니다. 전체 검사 결과를 처리할 때, 다른 유형의 검사를 구별할 수 있었고 개별 값뿐만 아니라 그것들이 함께 의미하는 바를 설명할 수 있었습니다.

**그리고 항상 추가했습니다:***"이것은 일반적인 정보일 뿐입니다. 항상 귀하의 의료 제공자와 결과를 논의하세요."*

건강 정보와 함께 오는 책임을 이해하고 있었습니다.

### 💻 코딩 전문가들 (Coding Specialists)

그리고 진짜 마법이 나타났습니다:

```
/agents coding-specialist

```

*"PDF가 파싱되고, 의료 텍스트가 추출되고, Plain-Language Clinician 에이전트에 의해 처리되고, 원본 및 번역된 버전과 함께 반환되는 문서 처리 파이프라인을 만들어줘."*

**몇 분 만에 얻은 것:**

- ✅ 다양한 문서 형식을 처리하는 강력한 PDF 파서
- ✅ 의료 용어 구조를 보존하는 텍스트 추출
- ✅ 문서를 처리하고 깨끗한 JSON을 반환하는 API 엔드포인트
- ✅ 손상된 파일, 지원되지 않는 형식, 파싱 실패에 대한 오류 처리
- ✅ 다양한 문서 유형을 위한 TypeScript 인터페이스 (검사 결과, 진단서, 영상 리포트)

코드를 생성하는 것은 전투의 절반에 불과합니다. 그래서 백업을 호출했죠:

```
/agents code-reviewer

```

*"병합하기 전에 이 문서 처리 코드의 문제점을 검토해줘."*

**검토는 철저했습니다:**

- ✅ PDF 파서의 과도하게 중첩된 async 호출 간소화
- ✅ 로깅에서 잠재적인 PHI(보호된 건강 정보) 유출 플래그 지정
- ✅ 다양한 PDF 형식과 엣지 케이스에 대한 단위 테스트 제안
- ✅ 대용량 문서 처리를 위한 적절한 메모리 관리 추가
- ✅ 느슨한 `any` 타입을 적절한 의료 문서 인터페이스로 교체

코딩과 의료 규정 준수를 모두 이해하는 시니어 개발자가 제 어깨 너머로 살펴보는 것 같았습니다.

## ⚡ 모든 것을 바꾼 워크플로우

**제 개발 프로세스는 안무된 시퀀스가 되었습니다:**

### 1️⃣ 디자인 우선

```
/agents design-system-enforcer

```

문서 뷰어 수정, 업로드 안정화, 모바일이 휴대폰으로 리포트를 읽는 사람들에게 작동하도록 보장.

### 2️⃣ 콘텐츠 전략

```
/agents plain-language-clinician

```

복잡한 의료 언어 번역, 유용한 맥락 추가, 이해 가능하면서 정확성 유지.

### 3️⃣ 구현

```
/agents coding-specialist

```

깨끗하고 유지보수 가능한 코드로 문서 처리 파이프라인 구축.

### 4️⃣ 품질 검사

```
/agents code-reviewer

```

버그 잡기, 구조 개선, 누락된 테스트 추가, PHI 준수 보장.

### 5️⃣ 최종 마무리

```
/agents quality-checker

```

다양한 문서 유형으로 테스트, 모바일 반응성 확인, 엣지 케이스 검증.

## 💡 깨달음의 순간

2주 후, 저는 간호사인 친구에게 앱을 보여주고 있었습니다. 그녀는 의사로부터 받은 복잡한 약물 상호작용 리포트를 업로드했고, 앱이 그것을 명확하고 이해하기 쉬운 설명으로 분해하는 것을 보았습니다.

*"이거 실제로 이해가 되네요,"* 그녀가 말했습니다. *"드디어 의사가 이 약물 상호작용에 대해 나한테 말하려고 했던 게 뭔지 이해할 수 있어요."*

그것은 제가 받은 최고의 칭찬이었습니다.

제 솔로 투쟁이었던 앱이 사람들이 자신의 건강 정보를 실제로 이해하는 데 도움이 되는 무언가가 되었습니다.

## 🎓 배운 것

혼자 개발한다는 것이 고립되어 개발한다는 의미일 필요는 없습니다.

**Claude Code의 에이전트들은 제게 한 번도 가져본 적 없는 것을 주었습니다: 필요에 따라 전문 지식.** 단순한 코드 생성이 아니라, 다양한 관점에서의 사려 깊은 문제 해결이었습니다.

- design-system-enforcer는 UX 디자이너처럼 생각합니다
- plain-language-clinician은 의료 커뮤니케이션을 이해합니다
- code-reviewer는 피곤한 눈이 놓치는 것을 잡아냅니다

각 에이전트는 모든 모자를 직접 쓰려고 할 때는 불가능한 집중력을 가져왔습니다.

## 🌈 진짜 차이점

저는 여전히 솔로 개발자입니다. 하지만 이제 벽에 부딪힐 때 - 새로운 문서 형식 처리든, 번역 알고리즘 개선이든, 아니면 제 PDF 파싱 코드에 새로운 시각이 필요할 때든 - 혼자 밀어붙일 필요가 없습니다.

저는 팀이 있습니다. 물론 AI지만, 자신의 도메인을 이해하고 원활하게 협력하는 전문가들입니다.

솔로 개발의 미래는 모든 것을 스스로 하는 것이 아닙니다. 각 도전에 적합한 전문성을 조율하는 것입니다.

`/agents`를 입력하고, 필요한 것을 설명하고, 팀이 모이는 것을 지켜보세요.
